# TextRepairo v0.1: original plan (historical)

> **Status: superseded.** This is the plan that was approved before v0.1.0 was built. Two things changed during the build: the app shell is **pywebview + PyInstaller** (not Tauri), and the tool is **GPL-3.0-or-later** (not MIT). The current plan is [v0.2-plan.md](v0.2-plan.md). "You" means the maintainer.

## 1. Problem and goals
Turn messy input (broken English, or any other language) into correct English in a chosen style: Fix only, Formal, Friendly, Prompt-style.

| Requirement | Decision |
|---|---|
| Free and open source | Open source. Only permissively licensed models are bundled or recommended. |
| Fully offline at runtime | No telemetry. A one-time model download is allowed. A model-file import covers air-gapped PCs. |
| Audience | The maintainer first, then everyone. Professional quality, not a demo. |
| Input languages | Any language. Output is English. |
| Platforms (v1) | Windows 10/11, macOS Apple Silicon, Linux. |
| Delivery order | Desktop app first. Web UI and CLI later. |
| Quality bar | "Good enough, user can review". Show a diff and allow regenerate. |

**Non-goals for v1:** mobile, browser extension, real-time typing assistance, output languages other than English, training a model from scratch.

## 2. Research findings
- A single small LLM is the right tool for multilingual grammar correction. A 2025 study of 17 models up to 9B found that one LLM can do it. Fine-tuning improved results. ([paper](https://arxiv.org/html/2505.06004v1))
- Small decoder-only models are viable for English grammar correction and easy to fine-tune. ([2026 paper](https://arxiv.org/html/2601.03874v1))
- Licensing shapes the model choice more than raw quality. Gemma is strong but uses Google's own terms. Grammarly's CoEdIT models are non-commercial (CC-BY-NC-4.0). Qwen3 models are Apache-2.0 (to be confirmed on the official cards before shipping).
- The packaging pattern of a bundled `llama-server` talking over localhost HTTP is well established.
- Caveat: results were from 2025 to early 2026. Newer permissive models may exist, so the model choice must be tested, not assumed.

## 3. Approach options considered
**Inference engine:** bundled llama.cpp `llama-server` (chosen) vs `llama-cpp-python` (no reliable GPU wheels), ONNX Runtime / Transformers.js (smaller model ecosystem), a specialised GEC model (English-only, no style control, non-commercial).

**App shell:** Tauri v2 + sidecars (planned) vs Electron vs a Python GUI. *Built instead:* pywebview + PyInstaller, because one process family is simpler to package and verify.

**Core logic:** Python core + FastAPI, packaged with PyInstaller (chosen).

**Quality strategy, in order of cost:** prompt engineering with few-shot examples; model-tier choice (Lite, Standard, Pro); optional second verify pass; LoRA fine-tune later if needed.

## 4. Target architecture
```
[Desktop window / browser / CLI]
          | HTTP on 127.0.0.1 only (per-launch token)
[textrepairo core (Python, FastAPI)]
   - prompt builder (mode)
   - chunker (paragraphs, sentence-aware)
   - post-processor (strip chatter, protect code, URLs, numbers)
   - model manager (download, verify hash, import, hardware-based recommendation)
          | HTTP on 127.0.0.1 only
[llama-server (llama.cpp)]  <-  GGUF model in the app data folder
```
- The core binds to loopback only and requires a launch token.
- Input text is wrapped in delimiters and treated as data, never as instructions (prompt-injection defence).
- Protected spans (code, URLs, emails, numbers) are masked before the model and restored after.
- Models are Q4_K_M GGUF files, SHA-256 checked on download and import.

## 5. Model plan
| Tier | Candidate | Approx. size | For |
|---|---|---|---|
| Lite | Qwen3-1.7B | about 1.2 GB | old laptops, 8 GB RAM |
| Standard (default) | Qwen3-4B-Instruct-2507 | about 2.5 GB | most PCs, CPU is fine |
| Pro | Qwen3-8B | about 5 GB | a GPU with 8 GB or more VRAM, or 16 GB+ RAM |

Qwen3-8B is a hybrid thinking model, so thinking mode is switched off for this task. Gemma, Llama and other restricted-license models are not bundled; a "bring your own GGUF" option lets advanced users load them at their own risk.

## 6. Phases
0. Approval gates: confirm model licences, choose name and repo.
1. De-risking spikes: model bake-off on a 60-sample set; llama-server on all three operating systems; packaging; offline proof.
2. Core engine and evaluation harness (`eval/`), with a regression rule that prompt or model changes must not lower scores.
3. Desktop app: text in/out, mode picker, diff view, copy, regenerate, streaming, cancel, first-run setup, settings, clear error states.
4. Packaging and release: Windows installer, macOS dmg, Linux AppImage and deb, licence notices.
5. Web UI and CLI.
6. Optional quality boost: LoRA fine-tune on synthetic data with clear dataset licences.

## 7. Risks and mitigations
| Risk | Mitigation |
|---|---|
| Small models over-paraphrase or change meaning | Strict Fix mode, low temperature, few-shot examples, protected spans, diff view, eval regression rule |
| Weak quality in rare languages | Larger tier, honest per-language notes, fine-tuning later |
| Prompt injection from pasted text | Delimited input, fixed system prompt, output filters, eval cases |
| Model licence mistakes | Verify official cards, ship notices, record licence per model |
| Cross-OS GPU and packaging problems | CPU fallback always, CI build matrix |
| Out-of-memory on weak PCs | Tier recommendation by RAM and VRAM, context limits, clear error message |

## 8. Definition of done for v1
- Installs and runs on Windows, macOS and Linux with no internet after the model is in place.
- All four modes work on any-language input, with streaming, diff view and cancel.
- Evaluation scores meet agreed thresholds; the Standard tier runs acceptably on CPU.
- All bundled and downloaded components have recorded, compatible licences.
- README, LICENSE, THIRD_PARTY_NOTICES and a contributor guide exist.
