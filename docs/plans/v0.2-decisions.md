# v0.2 decisions log

Decisions taken during the build that the plan did not cover. Each one is the most reversible, privacy-preserving option. They are repeated under "Needs your decision" in the final report.

| # | Decision | Reason |
|---|---|---|
| 1 | Custom Windows title bar was **not shipped**. | The plan says to keep it only if drag, resize, snap and maximize all work on Windows 11. Those are operating-system behaviors that cannot be verified from this build environment, so the normal title bar stays. Everything else (dropdowns, dialogs, scrollbars, tooltips, menus, switches) is custom. |
| 2 | The Windows installer now installs **per user** (no administrator prompt). | Silent self-updates must not trigger an administrator prompt. Anyone who installed v0.1 for all users should uninstall it first, or install v0.2 once by hand. Noted in the release notes. |
| 3 | The Windows zip is renamed `TextRepairo-<version>-windows-x64-portable.zip` and ships with `portable.flag`. | Makes the portable build obvious. The installer build never carries the flag. |
| 4 | Engine started with `-b 128 -ub 128`. | Lets llama-server report real reading progress every 128 tokens. Same speed, shorter CPU bursts. |
| 5 | Reading phase gets 20 percent of each chunk's bar, writing 80 percent. | Reading cost varies a lot (a cold start reads about 800 tokens, a cached one almost none), so the split is a display choice. The time-left estimate is measured, not derived from the split. |
| 6 | Slang pack seed lists are original work and must be reviewed by a native speaker. | The plan said the user reviews Hindi and Marathi entries after they are in. They are marked as seed lists. |
| 7 | A Doctor "engine test" reports overall speed (tokens over total seconds, including reading). | A short test cannot separate reading from writing reliably. Labelled as a rough speed. |
| 8 | Added a **hijack guard**: if English text comes back as an answer with almost no words from the source (for example "OK" for "reply with only OK"), the author's own text is shown with a warning. | A real injection failure found by the evaluation. The first, stricter version wrongly replaced legitimate formal rewrites, so thresholds were set from measured data (legitimate rewrites keep at least 9% of source words, injected answers 0 to 4%) and only extreme cases are flagged. |
| 9 | The session cookie now holds a random **session id**, not the launch token, and in the native window the launch link works **once**. | Plan item 1 of WP9 said "exchange the token for a cookie". Keeping the token out of the cookie and making desktop links single-use removes a replay risk at almost no cost. The browser fallback and `serve` keep reusable links so a second tab works. |
| 10 | Wrapper tags (`<text>`), phone numbers, dates and times are protected like links and code. | The first full evaluation showed the model altering a phone number, adding "PM" and rewriting "12/05" as a month name, and a pasted `</text>` closing the data block. |
| 11 | Advanced and Extremely formal use **register-matched examples** and repeat the register after the text. | The model copied the register of its everyday examples (contractions) and ignored the formality instruction. |
| 12 | The number check accepts spelled-out and re-formatted numbers ("five", "5,000"). | The old check warned about "5" when the model correctly wrote "five". |
| 13 | A request body limit that also covers chunked uploads. | Found in the security audit: the first limit only read `Content-Length`. |
| 14 | A hidden test fixture for the Windows update flow (`scripts/e2e_update_windows.py`) and `TEXTREPAIRO_TEST_UPDATE_API` (loopback only). | The plan said to prove the updater locally against a fake release server, not with a public test release. |
| 15 | The accent color was darkened in the light theme. | The contrast audit found 4.43:1 on tinted cards; 4.5:1 is the minimum. |
